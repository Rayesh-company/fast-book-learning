# صفر تا صدِ برنامک ایتا

راهنمای عملی راه‌اندازی مینی‌اپِ ایتا (ADR-0021): از ثبتِ بات در پنل ایتایار تا
گفت‌وگوی زنده با کتاب‌ها داخل ایتا. برنامک، **سومین کلاینتِ همان یک بک‌اند** است —
صفحۀ `/eitaa` را همین سرور سرو می‌کند و با همان توکنِ ورود، همان APIِ شیت و اپ
موبایل را حرف می‌زند. این سند فقط «به راه انداختن» آن است؛ قرارداد در §۱۱ِ
[صفر تا صد](zero-to-hundred.md) و تصمیم در [ADR-0021](adr/0021-the-eita-miniapp-the-bots-client-of-the-one-backend.md).

## ۰. پیش‌نیازها

| نیاز | چرا |
|---|---|
| **HTTPS سالم روی `booksai.rayesh-team.ir`** | WebView ایتا آدرس https باز می‌کند. بعد از مهاجرت سرور، بلاک ۴۴۳ نصب نیست؛ تا ران‌بوکِ TLS (پایین، §۶) اجرا نشود، برنامک داخل ایتا باز نمی‌شود حتی اگر همه‌چیز دیگر درست باشد. |
| دسترسی به پنل [eitayar.ir](https://eitaayar.ir) | ثبت برنامک و گرفتن توکن بات — کارِ مدیر محصول. |
| یک Account صادرشده روی پلتفرم | برنامک حساب نمی‌سازد (ADR-0013): کاربر اولین بار با ایمیل/گذرواژۀ همان Account وارد می‌شود و پیوندش ذخیره می‌شود. Account را از میز مدیریت (`/admin`) صادر کنید. |
| استک سرو روی جعبه | دیپلوی با CI انجام شده باشد (`Deploy to VPS` سبز) — مسیرهای `/eitaa/*` از قبل روی پروداکشن زنده‌اند. |

## ۱. ثبت برنامک و گرفتن توکن (پنل ایتایار)

1. در [eitayar.ir](https://eitaayar.ir) وارد شوید و بخش **برنامک/اپلیکیشن** را باز کنید
   (نام دقیق گزینه‌ها را پنل خودش تعیین می‌کند؛ مستندات رسمی:
   [developer.eitaa.com](https://developer.eitaa.com/docs/ManagementPanel)).
2. یک برنامک تازه بسازید و **آدرس وب** آن را بگذارید:

   ```
   https://booksai.rayesh-team.ir/eitaa
   ```

3. **توکن بات** را بردارید — رشته‌ای به شکل `12345678:AA...`. همین یک رشته هم کلید
   امضای initData است و هم اعتبارِ پیام سرور→کاربر؛ مثل LLM_API_KEY محرمانه بماند.
4. نام و یوزرنیم بات را همان چیزی بگذارید که کاربر جست‌وجو می‌کند (مثلاً «نشست»).
   برنامک روی کلاینت‌های **اندروید و ویندوز ایتا** اجرا می‌شود.

## ۲. تنظیم سرور (یک خط در `.env` جعبه)

روی جعبه، در `.env` کنار compose (خارج از git، دیپلوی آن را بازنویسی نمی‌کند):

```bash
cd /srv/chat-with-books/current
echo 'EITAA_BOT_TOKEN=12345678:AA...' >> .env
# اختیاری — زنگِ «پاسخ آماده شد» بعد از هر پاسخ استنادی (پیش‌فرض: خاموش؛
# سهمیۀ پیام روزانۀ ایتا مالِ ما نیست):
# echo 'EITAA_PUSH_ENABLED=1' >> .env
docker compose -p chat-withbooks -f compose.yaml -f compose.production.yaml --profile session up -d session
```

نشستِ اتصال‌ها (`EITAA_DB`) خودکار روی ولوم `/data/eitaa.sqlite3` می‌نشیند —
ریبیلد کانتینر پیوندِ هیچ کاربری را نمی‌پراند.

**تأیید تنظیم** (بدون توکن ۵۰۳ می‌دهد، با توکن ۴۰۱ — همین تمایز یعنی تنظیم شد):

```bash
curl -s -X POST https://booksai.rayesh-team.ir/eitaa/auth \
  -H 'Content-Type: application/json' -d '{"initData":"x"}'
# {"detail": "ورود از ایتا تأیید نشد؛ برنامه را از داخل ایتا باز کنید."}  ← درست
```

## ۳. اولین باز کردن داخل ایتا

1. در ایتا، بات را با یوزرنیمش پیدا کنید و برنامک را از منوی بات باز کنید.
   WebView صفحۀ `/eitaa` را باز می‌کند و ایتا کنار آدرس، `initData`ی امضاشده
   (شناسب کاربر + مُهر HMAC) می‌فرستد.
2. **باز شدن اول — درِ ورود**: چون initData نام هیچ Accountی را نمی‌آورد، صفحه
   فرم «ورود و پیوند» را نشان می‌دهد؛ همان ایمیل/گذرواژۀ Account پلتفرم. این
   بررسیِ اعتبار دقیقاً مسیر `/auth/login` خودِ شیت است (ایمیل ناموجود و
   گذرواژۀ غلط ۴۰۱ِ یکسان می‌دهند).
3. از باز شدن بعدی دیگر سؤالی نیست: سرور initData را با توکن بات تأیید می‌کند
   (الگوریتم شش‌مرحله‌ای HMAC — الگوریتم با مثال عددی خودِ مستندات ایتا وارسی
   شده)، از جدول پیوند (`/data/eitaa.sqlite3`) Account را برمی‌دارد و همان
   توکنِ معمولی ۱۲ساعته را می‌سازد. کاربر «فهرست نشست‌ها» را می‌بیند.
4. کاربرد: نشست را باز کنید، با «بپرس» بپرسید (همان خط لولۀ ask → quote-selection
   → quoted-answer)، نقل‌قول‌ها با هایلایت و صفحات می‌آیند، و خط «هزینۀ نشست:» از
   `/usage/live` می‌آید. «خروج از ایتا» فقط پیوندِ خودِ کاربر را برمی‌دارد.

## ۴. زنگِ ایتا (اختیاری)

با `EITAA_PUSH_ENABLED=1`، وقتی پاسخ استنادی یک نشست سِتل می‌شود و اپراتور
کنار برنامک نیست، به کاربرانِ ایتایِ متصلِ همان Account پیام
«پاسخ نشست شما آماده شد؛ از برنامک ادامه دهید.» می‌رسد (از
`eitaayar.ir/api/app/sendMessage`). قانونش در ADR-0021: زنگ است، هرگز رکورد؛
خرابیِ پلتفرم فقط یک زنگِ ازدست‌رفته است، نه پاسخِ ازدست‌رفته.

## ۵. عیب‌یابی

| نشانه | علت و چاره |
|---|---|
| صفحه می‌گوید «این صفحه از داخل ایتا باز می‌شود» | آدرس در مرورگر معمولی باز شده — SDK ایتا فقط داخل کلاینت ایتا ظاهر می‌شود. |
| ۵۰۳ «برنامک ایتا روی این سرور تنظیم نشده است» | `EITAA_BOT_TOKEN` در `.env` جعبه نیست یا کانتینر بعد از ویرایش up نشده. §۲ را تکرار کنید. |
| ۴۰۱ «ورود از ایتا تأیید نشد» | امضای initData نامعتبر یا کهنه است: باز شدن بیرون از ایتا، تغییر توکن در پنل بدون تغییر در سرور (یا برعکس)، یا اختلاف ساعتِ جدیِ جعبه. مُهر تا یک ساعت اعتبار دارد. |
| «ورود و پیوند» ۴۰۱ می‌دهد | ایمیل/گذرواژۀ Account نادرست است — همان پاسخ شیت. Account باید از قبل توسط مدیر صادر شده باشد؛ برنامک ثبت‌نام ندارد. |
| صفحه اصلاً باز نمی‌شود در ایتا | HTTPS هنوز روی دامنه نصب نیست (§۶)، یا آدرسِ ثبت‌شده در پنل با `/eitaa` یکی نیست. |
| پیام سرور→کاربر نمی‌رسد | کاربر باید یک بار برنامک را باز کرده باشد (دسترسی ارسالِ ایتا)؛ ضرب‌الاجل روزانۀ ایتا هم تمام شده باشد. |

## ۶. پیوست: ران‌بوک HTTPS (پیش‌نیازِ گام ۳)

بعد از مهاجرت سرور، برای booksai بلاک ۴۴۳ نیست و https به vhost همسایه می‌افتد.
رفعش یک‌بارِ دستِ ریشه است:

```bash
cd /srv/chat-with-books/current
certbot certonly --webroot -w /var/www/html -d booksai.rayesh-team.ir \
  --non-interactive --agree-tos --register-unsafely-without-email
f=$(grep -rl "booksai.rayesh-team.ir" /etc/nginx/sites-enabled /etc/nginx/conf.d | head -1)
cp "$f" "$f.bak" && cp ops/nginx/booksai.conf "$f"
nginx -t && systemctl reload nginx && curl -s https://booksai.rayesh-team.ir/livez
```

یا دائمی: به کاربر دیپلوی `NOPASSWD` برای `certbot` و `nginx` بدهید و در تب
Actions ورک‌فلوی **Fix TLS** را یک بار Run کنید — تمدید و این تعمیر از آن پس
خودکار است.

## ۷. کدها و تست‌ها (برای تغییرهای بعدی)

- صفحۀ برنامک: `ui/eitaa_app.html` — تمام رشته‌ها در جدول `S` (DRAFT، منتظر
  تأیید مدیر محصول؛ ردیف ۲۰۲۶-۱۰-۱۸ در `docs/CONTEXT.md`).
- پلتفرم ایتا: `ui/eitaa.py` (HMAC، sendMessage، push) و `ui/eitaa_store.py`
  (جدول پیوند).
- مسیرهای سرور: `/eitaa`، `/eitaa/auth`، `/eitaa/link`، `/eitaa/unlink` در
  `ui/serve.py`.
- قرارداد قفل شده در `tests/test_eitaa_app.py` — سبز بودن سوئیت، گیتِ هر push.
