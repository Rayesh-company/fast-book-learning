# ران‌بوک بازسازی سرور فحوا — بعد از پاک‌شدن سرور (۲۹ اکتبر ۲۰۲۶)

سرور پروداکشن (IP قبلی: در secret گیت‌هاب `DEPLOY_HOST`) پاک و نصب مجدد شد.
این برگه تا رساندنِ همه‌چیز به وضعیت قبل است: سایت سبز، تب ورود پیامکی،
استایل سالمِ `/mobile`، توکن برنامک `@fahvabook_app`.

مسیر تقسیم شده: **مرحلهٔ ۱ با شما روی سرور، بقیه با ایجنت.**

---

## مرحلهٔ ۰ — اگر IP عوض شد (۱ دقیقه)

- فقط IP جدید را به ایجنت بگویید (secret و کلید میزبان را خودش تازه می‌کند).
- در پنل کلادفلر، رکورد A هر دو دامنهٔ `fahva.rayesh-team.ir` (نام اصلی) و
  `booksai.rayesh-team.ir` (ریدایرکت قدیمی — APKهای نصب‌شده آدرس OTA را از
  همین نام می‌گیرند) را به IP جدید بدهید
  (حالت پروکسی/نارنجی همان بماند).
- اگر IP همان است: هیچ کاری لازم نیست، بگذرید.

## مرحلهٔ ۱ — روی سرور تازه (با کنسول/root پنل هاست، ~۱۵ دقیقه)

اگر هاست ایمیج «Docker نصب‌شده» دارد، همان را بگیرید و از دستور Docker صرف‌نظر کنید.

```bash
# ۱) کاربر دیپلوی — همین نام بماند که secretها معتبر بمانند
adduser cwdeploy
usermod -aG sudo cwdeploy

# ۲) Docker + پلاگین compose
curl -fsSL https://get.docker.com | sh
usermod -aG docker cwdeploy

# ۳) کلید عمومی دیپلوی برای Actions
su - cwdeploy
mkdir -p ~/.ssh && chmod 700 ~/.ssh
echo 'ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIJE2ENGh2PGc8j8Z2GhPhOSRmAqpt42nDHodrRzAaoGq zcode-booksai-origin-20261028' >> ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys
exit

# ۴) فایروال (اگر ufw خاموش است، باز کردن پورت‌ها در پنل هاست را هم چک کنید)
ufw allow 6041/tcp && ufw allow 80/tcp && ufw allow 443/tcp
```

⚠️ **فایروال پنل هاست (۲۹ اکتبر، تجربهٔ همین سرور):** جدا از ufw، لایۀ پنلِ
هاست هم فیلتر می‌کند و به‌طور پیش‌فرض فقط ۲۲ را رد می‌کند — تا 6041 و 80 و
443 در پنلِ هاست باز نشوند، هیچ اتصالی حتی به پورت‌های ufw-باز نمی‌رسد.

✅ تست مرحله: `docker --version` جواب بدهد و پورت ۲۲ از بیرون بسته نباشد.

## مرحلهٔ ۲ — بگویید «باز شد»؛ بقیه با ایجنت (~۳۰–۴۵ دقیقه)

1. کلید میزبانِ سرور تازه → secret گیت‌هاب (`DEPLOY_KNOWN_HOSTS`).
2. دیپلوی کامل از CI: سورس، کانتینرها، توکن برنامک `@fahvabook_app`،
   کلیدهای پیامکی فرازاسمس — **همان دیپلویی که استایل OTP و تب پیامکی و
   توکن را هم‌زمان می‌نشاند.**
3. ورک‌فلوی **Fix TLS**: وب‌سرور 443 و گواهیِ دامنه روی جعبهٔ تازه.
4. تأییدها: `livez` سبز · تب «ورود با پیامک» در سایت · `/eitaa/auth` با توکن
   درست جواب بدهد (نه ۵۰۳) · ورک‌فلوی **Bernamek check** هر دو لایه سبز.
5. پاک‌سازی ورک‌فلوی موقت `pin-deploy-host.yml`.

## مرحلهٔ ۳ — چیزهایی که با پاک‌شدن سوخت و باید دوباره ست شود

| چی | وضعیت | کار لازم |
|---|---|---|
| **`LLM_API_KEY`** (کلید هوش مصنوعی) | فقط روی جعبهٔ قبلی بود؛ CI آن را نمی‌نویسد | مقدارش را به ایجنت بدهید یا خودتان در `/home/chat-with-books/current/.env` بگذارید — **سؤال‌جواب بدون آن کار نمی‌کند** |
| حساب‌های کاربران (`accounts.sqlite3`) | ✅ تا حدی (۳۰ اکتبر) | حساب ادمین (`pm@`) در بوت خودش ساخته می‌شود و شمارهٔ مدیر (۰۹۰۲۱۱۰۰۹۳۹) دوباره با `/admin/attach` به آن بسته شد — لاگین پیامکی مدیر = حساب ادمین. سه کاربر واقعی از درِ باز پیامکی حسابِ صفرگرفته‌اند (۰۹۰۱۵۵۲۸۶۸۵، ۰۹۰۲۸۲۳۳۹۹۹، ۰۹۳۹۹۱۴۵۳۲۳) و هر پرسش‌شان ۴۰۲ «اعتبار تمام» می‌گیرد؛ تا شارژ از میز `/admin/topup` یا سیم‌کشی اشتراک ADR-0017، سؤال‌جواب برایشان «کار نمی‌کند» — با نبودِ حافظه اشتباه نشود (حافظه برگشته، probe بازیابی ۲۰۰). |
| پیوندهای ایتا (`eitaa.sqlite3`) | سوخت | هر کاربر یک بار دوباره از برنامک وارد شود؛ خودکار پیوند می‌خورد |
| صداهای درس (`lecture-audio`) | ✅ برگشت (۳۰ اکتبر) | زیپ `/home/ubuntu/fast-book-lecture-audio.zip` (۲۸ mp3 + ایندکس + SHA256SUMS) با همهٔ چک‌سام‌ها سبز در `/home/chat-with-books/lecture-audio/tarhe-kolli/` نشانده شد؛ هر ۲۸ نشست روی مسیر پخش‌کننده ۲۰۶ می‌دهد. دفعهٔ بعد: ورک‌فلوی Audio intake انتظار *پوشهٔ باز‌شده* دارد، نه زیپ |
| دیتای جست‌وجو (cognee) | ✅ برگشت (۳۰ اکتبر) | دامپ ۳۱۷مگ به `/home/chat-with-books/backups/cognee_db.dump` منتقل و با `pg_restore -U cognee -d cognee_db --clean --if-exists` داخل کانتینر postgres ری‌استور شد؛ شمارش‌ها == مرجع مهاجرت (۳۴۱ چانک، ۳۷۹۴ نهاد، ۱۸۶۴۱ یال، ۴۶۲۳ گره). کاربر پیش‌فرض تکراری که بوتِ تازهٔ cognee ساخته بود حذف شد تا دیتاست `tarhe-kolli` در tenant جاری دوباره ری‌سولو شود؛ probe بازیابی (همان payload خود `/ask`) ۲۰۰ با نقل‌قول واقعی از کتاب و کلید LLM هم ۲۰۰. بردارهای QA جلسه‌های بعد از ۱۲ سپتامبر در دامپ نبودند (۷۰ از ۲۴۰ در `SessionQAVector_text`) — بی‌ضرر، چون sqlite جلسات همان دوره در پاک‌شدن سوخته. |

## تست نهایی (وقتی همه‌چیز سبز شد)

1. سایت باز شود؛ تب «ورود با پیامک» با شمارهٔ خودتان کد بگیرد و وارد شوید.
2. داخل ایتا، از گفت‌وگوی `@fahvabook_app` برنامک باز شود و ورود کار کند.
3. یک نشست بسازید و یک سؤال بپرسید (این یعنی `LLM_API_KEY` هم درست نشسته).
